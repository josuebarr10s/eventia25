# Auditoría académica de las siete APIs

## Alcance y fuentes

Esta auditoría clasifica los siete escenarios intencionalmente inseguros de la consigna oficial de la Actividad 23. Son escenarios académicos, no evidencia automática del Eventia instalado. Se revisó aparte el código actual en [auditoría del proyecto real](05-AUDITORIA-CODIGO-REAL.md).

La consigna oficial es el PDF **Actividad 23 P Web**. El PDF **Actividad 23** se usó solo como referencia de redacción y razonamiento: describe vistas HTML/sesiones y rutas distintas; esas afirmaciones no se trasladaron al sistema actual, que sí contiene API REST con DRF y autenticación JWT.

## Matriz de los escenarios

| API | Problema identificado | Consecuencia | Riesgo OWASP API Security 2023 principal | Riesgos secundarios | Solución propuesta |
|---|---|---|---|---|---|
| 1. `GET /api/inscripciones/125` | Comprueba existencia, pero no que el solicitante sea dueño; devuelve nombre y correo. | Lectura horizontal de inscripciones e información personal. | **API1 BOLA**: autorización insuficiente del objeto identificado por ID. | **API3 BOPLA** si se exponen propiedades personales innecesarias. | Filtrar por propietario o permiso de objeto explícito; responder 404 para objeto ajeno/no visible; allowlist de respuesta. |
| 2. `POST /api/usuarios` | Acepta `rol` y persiste el valor del cliente; permite `123456`. | Escalada a administrador; si la contraseña se reutiliza o se adivina, toma de cuenta. | **API3 BOPLA**: propiedad de rol modificable por quien no está autorizado. | **API2 Broken Authentication** por política de contraseña débil. | Rechazar campos extra; asignar rol básico en servidor; validar contraseña con el framework y guardar solo hash; limitar altas. |
| 3. `POST /api/eventos` | Cualquier cuenta autenticada puede invocar la función; admite cupo y precio negativos. | Creación/publicación por participante; datos inválidos e inconsistencias de dominio. | **API5 BFLA**: falta autorización para la función de crear. | Capacidad/precio inválidos son fallas de validación e integridad del dominio, no una categoría OWASP API por sí solos. **API3** solo aplicaría si un campo sensible puede cambiar sin autorización de propiedad. | Exigir permiso de crear; vincular organizador a la identidad; validar límites y formato en servidor; rechazar propiedades no permitidas. El precio es solo parte del ejemplo académico; Eventia no tiene ese campo. |
| 4. `PUT /api/eventos/25` | Comprueba rol de organizador, pero no propiedad del evento. | Un organizador sobrescribe eventos de otro organizador. | **API1 BOLA**: el acceso al objeto no se autoriza por ID/propietario. | **API5** solo si la función de editar también se concede a roles sin permiso; el defecto descrito principalmente es de objeto. | En cada mutación comprobar permiso de función y propietario; permitir administración global solo con permiso explícito; limitar campos editables. |
| 5. `POST /api/eventos/25/inscripciones`, `cantidad: 500` | Cantidad sin límite por persona y control de cupos no atómico bajo concurrencia. | Automatización puede acaparar plazas; doble asignación o sobrecupo por carrera. | **API6 Sensitive Business Flows**: se expone un flujo de reserva susceptible de automatización dañina. | **API4** si volumen/operaciones agotan CPU, almacenamiento, correo o capacidad; una carrera de sincronización se clasifica mejor como **CWE-362**, no como categoría OWASP automática. | Definir una plaza por usuario para este MVP, limitar el flujo, bloquear/revisar capacidad dentro de transacción y asegurar unicidad en la base. |
| 6. `GET /api/usuarios/35` | Serializa todos los campos, incluido `passwordHash`. | Exposición de hash de credenciales y datos personales; aumenta el impacto de otro incidente. | **API3 BOPLA**: respuesta expone propiedades sensibles sin necesidad. | **API1 BOLA** si el ID permite consultar perfiles ajenos sin política de objeto. | Usar serializer allowlist; no incluir contraseñas ni hashes; restringir perfil al dueño y permitir acceso administrativo solo con permiso y propósito explícitos. |
| 7. `POST /api/auth/login` | Sin límite de intentos; mensajes diferentes revelan si un correo está registrado. | Fuerza bruta/spraying y enumeración de cuentas. | **API2 Broken Authentication**. | **API4** si volumen de intentos consume recursos; la enumeración sigue perteneciendo al riesgo de autenticación. | Contadores temporales atómicos, respuesta uniforme para credenciales erróneas, `429` con `Retry-After`, y cache/monitorización apropiados. Evitar bloqueos permanentes de cuenta que habiliten DoS. |

## Cómo se asignó OWASP

- **API1 BOLA** se usa cuando una petición con ID manipulable llega a un objeto sin comprobar la relación entre actor y recurso.
- **API2 Broken Authentication** cubre fallos en la identificación o verificación de credenciales, incluida protección insuficiente del login.
- **API3 BOPLA** agrupa lectura excesiva de propiedades y asignación masiva de atributos que el actor no puede cambiar.
- **API4 Unrestricted Resource Consumption** trata límites inadecuados de consumo técnico y costos por solicitud; no toda regla de negocio es API4.
- **API5 Broken Function Level Authorization** es acceso a una acción privilegiada como crear eventos sin permiso funcional.
- **API6 Unrestricted Access to Sensitive Business Flows** se centra en automatizar un flujo legítimo (por ejemplo, reservar plazas) de forma que perjudica el servicio o a sus usuarios.

La carrera de cupos también se puede describir con CWE-362 (concurrencia). Se documenta así sin forzarla dentro de API4 o API6: API6 explica el abuso automatizado del proceso de reserva; CWE-362 describe el defecto de sincronización que puede hacer que dos operaciones sobrepasen la misma capacidad.

OWASP API Security Top 10 2023 es diferente del OWASP Top 10 web 2021. La matriz completa de categorías oficiales está en [OWASP API Security 2023](https://api-security.owasp.org/editions/2023/en/0x11-t10/); ver en particular [API1](https://api-security.owasp.org/editions/2023/en/0xa1-broken-object-level-authorization/), [API2](https://api-security.owasp.org/editions/2023/en/0xa2-broken-authentication/), [API3](https://api-security.owasp.org/editions/2023/en/0xa3-broken-object-property-level-authorization/), [API4](https://api-security.owasp.org/editions/2023/en/0xa4-unrestricted-resource-consumption/), [API5](https://api-security.owasp.org/editions/2023/en/0xa5-broken-function-level-authorization/) y [API6](https://api-security.owasp.org/editions/2023/en/0xa6-unrestricted-access-to-sensitive-business-flows/).
